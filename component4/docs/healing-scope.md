# Healing scope

## Scope statement

Healing repairs one thing: a single `find_element` locator in a test that C4
generated, when the test failed because the element was not found
(`locator_not_found`). It replaces that locator with a different locator for
the most semantically similar element on the screen captured at the failure,
only when the confidence, ambiguity, and uniqueness checks pass. The repaired
script is re-run before it is reported as verified.

## In scope and out of scope

| Area | In scope | Out of scope |
|---|---|---|
| Failure type | `locator_not_found` (`NoSuchElementException`) | Script, infrastructure, element-state, and unknown failures |
| Scripts | Scripts generated by C4, with `step_N` functions that use string-literal locators | Hand-written or otherwise structured scripts |
| Evidence | Page source captured at the failure; optional stored baseline | Inventing hierarchy, locator, or device state |
| Actions | The locator of a `find_element(...).click()` (tap) or `.send_keys()` (input) step. Other `find_element` calls have no action constraint | Adding or changing actions, credentials, or destructive behavior |
| Locators read | ID, accessibility ID, UiSelector text, and XPath from the failed step | |
| Locators written | ID, accessibility ID, or UiSelector text, chosen in that order when unique | Generating XPath |
| Output | A new versioned script after policy approval | In-place modification after refusal |
| Retry | Bounded by `max_heal_rounds` (default 3) | Unbounded retries or recovery from unrelated failures |
| Platform | Android with Appium UiAutomator2 | iOS and other drivers |

## Failure kinds

| Kind | Healed? |
|---|---|
| `locator_not_found` | Yes |
| `element_state` (stale, not interactable, click intercepted) | No |
| `infrastructure` (connection, session, timeout) | No |
| `script_error` (syntax, import, name) | No |
| `unknown` | No |

A locator swap cannot fix the other kinds, and attempting it would hide real
defects.

## Pipeline

1. Read the failed step's locator and action from the script (libcst).
2. Parse the failure-time page source.
3. Narrow candidates with rules R1 to R7.
4. Rank the remaining candidates by semantic similarity to the original
   element (Sentence-BERT by default; a lexical embedder is available).
5. Apply the policy and require a unique replacement locator.
6. Rewrite only that locator in the script (libcst) and add an audit comment.
7. Save a new version and re-run it on the device.

## Narrowing rules

| Rule | Removes a node that is |
|---|---|
| R1 | Disabled, or without usable on-screen bounds |
| R2 | From a different app package than the original element |
| R3 | Incompatible with the action: a tap needs a clickable, focusable, or clickable-parent node, or one in the same widget family as the original; an input needs a text field |
| R4 | In a different widget family (button, text field, text, image) than the original |
| R5 | Without text, content description, or resource id |
| R6 | Unchanged compared with the baseline screen (only when a baseline exists) |
| R7 | A plain layout container with no text and not clickable |

## Policy defaults

| Setting | Default |
|---|---|
| Confidence threshold | 0.5 |
| Ambiguity margin | 0.05 |
| Maximum heal rounds | 3 |
| Candidates ranked | 300 |
| Top candidates reported | 5 |

A repair is accepted only when the best score reaches the threshold, the
runner-up does not score within the margin when it also reaches the threshold,
and the replacement locator matches exactly one element on the screen.

## Safety rules

1. A refusal is a valid result. The original script remains unchanged.
2. Candidates must pass action compatibility and narrowing rules before
   semantic ranking.
3. A baseline can remove unchanged nodes; without one, the decision records
   that this structural rule was skipped.
4. Healing requires the configured confidence threshold and the ambiguity
   margin/uniqueness policy.
5. Every accepted repair is written as a separate script and repository
   version with its parent and decision metadata.
6. The rerun loop stops after a pass, refusal, non-locator failure, missing
   page source, or the configured round limit.
7. Telemetry-only fallback descriptors use only the locator and selected
   journey context; they do not dump an entire context object.

## What verified means

A repair is reported as verified only when the repaired script is re-run on the
device and passes. Generated tests contain no business assertions, so this
shows that the replay succeeds, not that the application behavior is correct.
A suggested repair that has not been re-run is reported as suggested only.

## Limitations and future scope

- The desktop demo runs the lexical embedder and captures no baseline, so rule
  R6 is skipped there.
- Healing does not cover timing, element-state, or flow changes such as an
  inserted screen. Each would need its own repair and safety rule.
