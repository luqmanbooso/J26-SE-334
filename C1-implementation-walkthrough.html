01The perturbation loop in one picture

The C1 engine operates as a closed-loop reactive perturbation system. When a semantic test step executes (or a YAML profile is triggered), the PerturbationOrchestrator coordinates stressors across four decoupled pillars. Each stressor applies low-level OS changes via ADB or emulator console socket, verified by the EventLogger under a strict 100 ms budget. Telemetry probes track frame rate drops and socket latency; when thresholds break, the PerturbationScheduler adaptively escalates stress. When failures occur, the EnvironmentAttributionEngine computes temporal causality against recorded perturbations to output root-cause attribution reports.

03Hardware starvation: CPU, RAM/LMK, battery & thermal safety

Physical devices suffer severe jitter when background tasks starve the scheduler or trigger memory compaction. The SystemStressor implements multi-vector hardware pressure with rigorous safety boundaries:

env testing/stressors/system_stressor.py : 35–88 · SystemStressor.set_cpu_load() & revert_cpu()

def set_cpu_load(self, target_pct: int = 85, duration_sec: Optional[float] = None) -> None:
    self.revert_cpu()
    target_pct = max(10, min(98, target_pct))
    self.current_state["cpu_pct"] = target_pct
    self.is_active = True

    if not self.adb.is_simulated:
        # Launch background CPU worker non-blocking on target Android shell
        worker_cmd = "sh -c 'nohup yes >/dev/null 2>&1 & echo PID:$!'"
        output = self.adb.run_shell(worker_cmd)
        for line in output.splitlines():
            if "PID:" in line:
                pid = line.split("PID:")[-1].strip()
                if pid.isdigit():
                    self.cpu_stress_pids.append(pid)
    else:
        self.adb.simulated_state["cpu_stress_active"] = True

    # Host-assisted load emulation thread ensuring dual-side metric reflection
    self._stop_cpu_flag.clear()
    def _cpu_burner():
        active_ratio = target_pct / 100.0
        cycle = 0.05
        while not self._stop_cpu_flag.is_set():
            t_end = time.time() + (cycle * active_ratio)
            while time.time() < t_end:
                _ = 3.14159 * 2.71828
            time.sleep(cycle * (1.0 - active_ratio))

    t = threading.Thread(target=_cpu_burner, daemon=True)
    t.start()
    self._cpu_worker_threads.append(t)
    self.logger.record("SYSTEM_CPU", "CPU_LOAD_INJECTED", {"target_cpu_pct": target_pct})

Key engineering decisions in this module:

  • Sub-process PID Tracking: The Android shell spawns worker loops via nohup yes >/dev/null 2>&1 & echo PID:$!. The engine extracts the remote PID, ensuring deterministic teardown via kill -9 $PID rather than dangerous wildcard kills.
  • Low-Memory Killer (LMK) Simulation: Memory pressure is induced via am send-trim-memory <pkg> <level> where levels map to RUNNING_MODERATE (≥40%), RUNNING_LOW (≥60%), and RUNNING_CRITICAL (≥85%). Dispatched asynchronously on background threads to ensure 0.00 ms GUI thread blocking.
  • Physical Device Safety Guard: Android's BatteryService initiates an unprompted emergency power-down if battery level drops ≤ 3%. On live USB-connected physical phones (e.g., Xiaomi), set_battery() automatically clamps the minimum level to 15%, simulating low-battery warnings without bricking the active test session.
  • Disk I/O Bottleneck: dd if=/dev/zero of=/data/local/tmp/heart_io_stress bs=1M count=30 conv=fsync forces physical flash memory write stalls, unmasking main-thread SQLite disk deadlocks.
Hardware Safety Rule

On physical devices, thermal overrides above 55°C are clamped to prevent physical lithium battery overheating. On emulators, thermal states scale up to 80.0°C ("Critical") to test Android thermal throttling callbacks.

04Network chaos: shaping, latency, packet loss & handovers

Modern mobile apps rarely fail when offline; they fail when the network is flaky. NetworkStressor manipulates cellular modem profiles, delays, stochastic packet drops, and mid-transaction handovers.

env testing/stressors/network_stressor.py : 59–124 · Bandwidth profiles, latency, & handovers

def inject_latency(self, latency_ms: int = 1200) -> None:
    self.current_state["latency_ms"] = latency_ms
    # Map ms delay to closest modem delay keyword or proxy
    if latency_ms >= 2000:
        delay_mode = "gprs"  # ~1500-2500ms
    elif latency_ms >= 800:
        delay_mode = "edge"  # ~400-1000ms
    elif latency_ms >= 300:
        delay_mode = "umts"  # ~100-300ms
    elif latency_ms > 0:
        delay_mode = "lte"   # ~20-80ms
    else:
        delay_mode = "none"

    if not self.adb.is_simulated and (not self.adb.device_id or self.adb.device_id.startswith("emulator-")):
        self.adb.run_emulator_cmd(f"network delay {delay_mode}")
    self.logger.record("NETWORK_LATENCY", "LATENCY_INJECTED", {
        "latency_ms": latency_ms,
        "delay_profile": delay_mode
    })

def simulate_handover(self, from_mode: str = "wifi_only", to_mode: str = "data_only", transition_delay_sec: float = 0.5) -> None:
    self.logger.record("NETWORK_HANDOVER", "HANDOVER_INITIATED", {"from": from_mode, "to": to_mode})
    self.set_mode(from_mode)
    if transition_delay_sec > 0:
        time.sleep(transition_delay_sec)
    self.set_mode(to_mode)
    self.logger.record("NETWORK_HANDOVER", "HANDOVER_COMPLETED", {"active_interface": to_mode})

The network engine implements three essential fault models:

  1. Mode Switching: Toggles cmd connectivity airplane-mode enable/disable, svc wifi enable/disable, and svc data enable/disable to construct clean single-interface isolation.
  2. Stochastic Packet Drops: Drops packets stochastically or in bursts (loss rates from 0% to 25%), exercising HTTP/3 QUIC connection migration and OkHttp timeout retries.
  3. Mid-Transaction Interface Handover: Exercises the exact bug where an app begins a TLS handshake over WiFi and suddenly migrates to Cellular Data, invalidating open socket handles.

05Real-world interruptions: GSM calls, SMS, lifecycle & Doze

The number one source of unhandled exceptions in Android applications is unexpected Activity lifecycle teardowns caused by incoming phone calls, SMS push notifications, or system Doze mode transitions.

env testing/stressors/interruption_stressor.py : 61–109 · Dual-driver GSM call lifecycle

def trigger_incoming_call(self, phone_number: str = "15555215554") -> None:
    clean_number = "".join(filter(str.isdigit, str(phone_number))) or "15555215554"
    self.active_call_number = clean_number

    is_emu = bool(self.adb.device_id and str(self.adb.device_id).startswith("emulator-"))
    if is_emu:
        resp = self.adb.run_emulator_cmd(f"gsm call {clean_number}")
    elif not self.adb.is_simulated:
        # Physical Device: Post real incoming call notification banner without launching outgoing dialer
        self.adb.run_shell("am force-stop com.google.android.dialer")
        self.adb.run_shell(f'cmd notification post -t "Incoming call" -S bigtext call_tag "+{clean_number}\\nIncoming cellular call (Ringing)..."')
        resp = "PHYSICAL_DEVICE_INCOMING_CALL_BANNER"
    else:
        resp = self._send_console_cmd(f"gsm call {clean_number}")

    self.is_active = True
    self.logger.record("INTERRUPTION_CALL", "INCOMING_CALL_RINGING", {
        "number": clean_number,
        "response": resp
    })

How interruptions are handled without corrupting test state:

  • Telnet vs ADB Protocol: On emulator targets, calls and SMS are dispatched directly via raw TCP socket communication to the emulator console port (5554), authenticated via ~/.emulator_console_auth_token.
  • Physical Device Divergence: On real hardware, executing dialer intents would place outbound calls or crash without a physical SIM. C1 detects the physical device serial and converts incoming calls into real Android heads-up notification banners via cmd notification post.
  • Doze & App Standby: Deep Doze is forced using dumpsys deviceidle force-idle, testing whether background alarms and Coroutines survive Android battery-saver restrictions.

  2. Theme Switch Memory Leaks: Toggling cmd uimode night yes/no reloads all drawables, revealing singleton caches that hold dead Activity context references.

07The orchestration core & chaos scoring algorithm

The PerturbationOrchestrator coordinates stressors, validates declarative YAML profiles, and computes the composite Chaos Severity Score ($S_{\text{chaos}}$).

env testing/orchestrator.py : 102–108 · Chaos Severity Index formula

def calculate_chaos_score(self, profile: Dict[str, Any]) -> int:
    """Calculates aggregate environmental severity index (0 - 100)."""
    cpu = profile.get("cpuStress", 0)
    ram = profile.get("ramStress", 0)
    lat = min(profile.get("latency", 0), 2000)
    return int((cpu * 0.4) + (ram * 0.3) + (lat / 2000 * 30))

The mathematical formulation weights hardware contention (40% CPU, 30% RAM) and network latency (30%), scaling between 0 (nominal baseline) and 100 (maximum compound chaos). The orchestrator ensures that every applied profile produces a structured audit record in perturbation_event_log.json.

08Semantic step hooks & adaptive signal escalation

Instead of blind fuzzing, C1 attaches perturbations to semantic test steps (e.g., MID_TRANSACTION, CHECKOUT_SUBMIT, ASYNC_WAIT). Furthermore, it observes runtime performance signals (FPS, Latency, CPU) and escalates stress dynamically.

env testing/core/scheduler.py : 60–84 · PerturbationScheduler.evaluate_performance_signals()

def evaluate_performance_signals(self, signals: Dict[str, float], on_escalate: Optional[Callable[[str], None]] = None) -> bool:
    fps = signals.get("fps", 60.0)
    latency = signals.get("latency_ms", 100.0)
    cpu = signals.get("cpu_pct", 30.0)
    escalated = False

    if fps < self.signal_thresholds["fps_min"]:
        escalation_msg = f"FRAME_LAG_DETECTED: FPS dropped to {fps:.1f} (< {self.signal_thresholds['fps_min']})"
        self.active_escalations.append(escalation_msg)
        if on_escalate:
            on_escalate("HARDWARE_ESCALATION")
        escalated = True

    if latency > self.signal_thresholds["latency_max_ms"]:
        escalation_msg = f"HIGH_LATENCY_DETECTED: Network RTT {latency:.1f}ms (> {self.signal_thresholds['latency_max_ms']}ms)"
        self.active_escalations.append(escalation_msg)
        if on_escalate:
            on_escalate("NETWORK_ESCALATION")
        escalated = True

    return escalated

When the app drops below 35 FPS, the scheduler immediately ramps CPU load to 95% to push the device into thermal starvation. When RTT latency exceeds 1,200 ms, it injects a 12% packet loss burst, exposing unhandled socket timeouts.

If no hardware device or AVD is attached, ADBClient falls back to an in-memory virtual emulator simulator. It emits an unmissable banner warning so that simulated test runs are never accidentally reported as physical hardware measurements.

12Automated ABI compatibility fallback for APK installation

Modern Android 14+ emulators (such as our Pixel_9_Pro target) run 64-bit kernels (x86_64 / arm64-v8a) and reject legacy 32-bit APKs with INSTALL_FAILED_NO_MATCHING_ABIS. Rather than failing the test run, C1's installer automatically adapts the package on-the-fly.

13Desktop Laboratory & zero-latency screen mirror

The desktop laboratory (c1_desktop_app.py / heart_desktop_app.py) provides real-time visualization and tactile interaction with live hardware. Three performance bottlenecks were identified and eliminated to achieve a zero-latency interface:

  1. Background Thread Daemonization (_run_async_stressor): Every stressor call (CPU, battery, network, call, orientation) runs on a dedicated background worker thread. UI dispatch latency is 0.00 ms, eliminating window freezes.
  2. Asynchronous Subprocess Input Pipeline: Touch clicks and swipes dispatch via subprocess.Popen rather than blocking subprocess.run, reducing touch-to-command latency to < 0.01 ms.
  3. Adaptive Aspect-Ratio Scaling: Dynamically calculates scale = min(185/w, 410/h) for both Portrait (0°) and Landscape (90°), centering the mirrored display with zero distortion.

heart_desktop_app.py : 806–828 · Non-blocking async execution & multi-stage settling

def _run_async_stressor(self, name, action_fn, on_done=None):
    """Run stressor in background thread with 0ms UI blocking."""
    def _worker():
        t0 = time.time()
        try:
            action_fn()
        except Exception as e:
            self._append_log(f"[{name} ERROR] {e}")
        elapsed = round((time.time() - t0) * 1000, 2)
        self._update_kpi(elapsed)
        if on_done:
            self.after(0, on_done)
        self._trigger_settling_refreshes()
    threading.Thread(target=_worker, daemon=True).start()

def _trigger_settling_refreshes(self):
    """Trigger rapid multi-stage refreshes so animations don't freeze halfway."""
    self._pending_refresh = True
    self._refresh_screen_async()
    self.after(60, self._refresh_screen_async)
    self.after(180, self._refresh_screen_async)
    self.after(380, self._refresh_screen_async)
