1. System Architecture

Component 3 acts as the autonomous visual oracle within the multi-agent UI testing framework. It inspects live Android application interfaces, detects visual and functional layout bugs across 7 taxonomies, maps pixel anomalies back to physical device coordinates, and outputs canonical scientific envelopes.

Core Scientific Guarantees
  • Air-Gapped Local Inference: No external API calls (zero OpenAI/Anthropic network calls); 100% runs on internal NVIDIA RTX 3050.
  • Zero VRAM Leaks: Model loads once into GPU memory upon FastAPI lifespan startup and stays pinned; zero reload overhead per inference cycle.
  • Deterministic Bounds: Defect bounding boxes are validated against physical screen boundaries and guaranteed invertible.

4. Spatial Tiling & Defect Capacity Mechanics

A critical question during the oral defense is how a model trained on single defects can detect multiple visual bugs across a mobile screen.

Spatial Divide-and-Conquer Architecture

Mobile screens have tall aspect ratios (e.g. 9:20 or 1080x2400). Scaling down the entire screen directly causes tiny text and button icons to become unreadable blur. Our spatial tiling engine solves this:

MechanismExecution LogicAcademic Scientific Rationale
Independent View Inference Each vertical crop is fed independently into the QLoRA model. High native resolution preserved without downsampling artifacts.
Invertible Coordinate Projection [x1, y1, x2, y2] are translated back using slice offsets. Zero coordinate drift; bounding boxes match real screen pixels exactly.
Class-Aware IoU Clustering Overlapping slices evaluated. Same defects merged if IoU ≥ 0.5. Prevents double-counting bugs seen in the tile overlap region.
PP1 Scope Declaration scope: {"mode": "single_primary_visual_finding", "exhaustive": false} Honest academic demarcation: avoids claiming unverified exhaustive detection.

5. Common Autonomous Test Execution Driver Layer

The unified autonomous crawler in common/driver.py connects to live Android devices, explores interactive UI nodes, and dispatches screens directly to C3 Vision Oracle.

Running the Autonomous Test Crawler
python -m common.driver --package com.solvance.android --steps 10 --output results/crawler_report.json

Autonomous Crawl Lifecycle

  1. Cross-Process File Lock: Acquires exclusive OS lock on .adb_{serial}.lock to eliminate multi-process contention.
  2. Live Screenshot & Hierarchy Capture: Calls AdbDevice.screencap() and AdbDevice.dump_hierarchy() in sub-250ms burst.
  3. Oracle Evaluation: Posts capture to C3 REST API v2 and registers verdict.
  4. Interactive Target Extraction: Parses XML hierarchy to find clickable buttons, text inputs, and tabs.
  5. Gesture Dispatch & Settle Window: Sends input tap x y and awaits UI animation settle window (500ms).
  6. Report Generation: Writes complete traversal trace and detected visual bugs to JSON.

7. Thesis Oral Defense Q&A Bank

Memorize these precise answers for technical defense examination questions.

Q1: Why use spatial tiling instead of feeding the full 1080x2400 screen directly?

Examiner Question: "Why do you decompose the image into slices? Doesn't the Vision Transformer take any arbitrary resolution?"

Authoritative Answer: "Mobile screens feature tall aspect ratios (9:20). Passing a 1080x2400 screenshot directly into a standard vision-language backbone downsamples or collapses text and small touch targets below readable pixel thresholds. By dividing the screen into three overlapping crops plus one global downscaled view, our pipeline preserves high spatial frequency information, enabling accurate identification of small-scale component occlusions and single-line text truncations while keeping VRAM well under the 4GB hardware budget."

Q2: How do you justify detecting multiple bugs when your model was trained on single defects?

Examiner Question: "Your LLaMA-Factory fine-tuning script trained on single-defect bounding box annotations. How can you claim multi-defect detection?"

Authoritative Answer: "We strictly distinguish between tile-level model capacity and system-level pipeline capacity. In any individual slice, the model detects the most salient visual defect. When distinct defects exist across different screen regions (e.g., an occluded navbar at the top and truncated disclaimer text at the bottom), independent tile inferences capture each anomaly. Our IoU clustering engine aggregates non-overlapping candidates into the findings: [...] list. Furthermore, to maintain strict scientific integrity, our Canonical Contract v2 declares scope: {'mode': 'single_primary_visual_finding', 'exhaustive': false}, ensuring we never falsely claim exhaustive multi-defect certification before dedicated multi-label fine-tuning is completed."

Q3: How do you guarantee the model does not hallucinate out-of-bounds coordinates?

Examiner Question: "VLMs frequently produce coordinates outside image boundaries. How does your backend safeguard against this?"

Authoritative Answer: "Contract v2 enforces runtime schema invariants via Pydantic model validators. Coordinate parsing validates physical ordering (x1 < x2 and y1 < y2) and non-negativity. When un-tiling, coordinates are strictly clamped to physical screenshot resolution (e.g. x2 ≤ width, y2 ≤ height). Any violation raises an explicit invariant error and marks the verdict as error or inconclusive rather than generating a corrupted verdict."

Q4: How does your system satisfy the 1500ms latency requirement on a 4GB laptop GPU?

Examiner Question: "How can a 2-billion parameter multimodal model achieve interactive test execution speeds on a consumer laptop?"

Authoritative Answer: "We apply 4-bit QLoRA weight quantization and eager memory pinning. The base model weights and LoRA adapters are loaded into VRAM once upon FastAPI server initialization, avoiding repeated weights loading. By using PyTorch 2.6 CUDA 12.6 flash attention kernels, single-tile inference completes in approximately 700ms, comfortably satisfying the 1500ms SLA target."

8. Troubleshooting Guide

Error SymptomRoot CauseImmediate Fix
HTTP 503: No ADB device attached Emulator or physical phone not detected by ADB daemon. Run adb devices; restart daemon with adb kill-server && adb start-server.
HTTP 404: Capture ID 'cap_xxx' not found Job was dispatched with a capture ID from a previous database wipe. Run POST /v2/captures first, grab the returned capture_id, and pass it to POST /v2/jobs.
CUDA out of memory Another process (e.g. Ollama or browser hardware acceleration) occupied VRAM. Run nvidia-smi; terminate competing processes; ensure only C3 server runs on GPU.
HTTP 409: Job already completed/cancelled Attempting to cancel an already finished job. Job state transitions are immutable once terminal (COMPLETED, FAILED, CANCELLED).
